# PrimeTrack Nigeria — Complete Website Rebuild & Modernization

> **Status note (added at intake):** This is the *visual direction* document. Where it
> conflicts with `primetrack-build-brief.md`, **the build brief wins** — specifically on
> stack (Astro + React islands + Tailwind, not a React SPA), on the audit (already done;
> do not crawl the live site), and on warranty wording (**3 years**, never "Lifetime").

We are going to completely rebuild and overhaul the existing **PrimeTrack Nigeria website** using **React**.

The existing website is:

**https://www.primetracknigeria.com**

The current website was built with WordPress and has a dated/legacy visual style. It relies heavily on basic boxes, text blocks, static images, and conventional WordPress layouts.

Our goal is **not** to simply convert the existing WordPress website into React.

We want to **rethink and redesign the entire website experience** while preserving all of the useful information and functionality currently available.

The final result should feel like a modern, credible, premium technology/telematics company website.

---

## 1. FIRST: Thoroughly Audit the Existing Website

Before writing or changing any code, thoroughly inspect:

**https://www.primetracknigeria.com**

Go through the website page by page.

Do not make assumptions about its content.

Study and document:

* Every page
* Every menu item
* Every submenu
* The current navigation structure
* All written content
* Services
* Products
* Solutions
* Industries
* Company information
* Contact information
* Calls to action
* Images
* Forms
* Footer content
* Existing links
* Any useful UI/UX patterns
* Any important information buried inside individual pages

The new website must **retain the information contained in the current website** unless there is a strong UX reason to restructure how that information is presented.

Do not accidentally remove useful content simply because the current website is poorly designed.

Think of the current website as the **content and business-information source**, while the new website will be the **modernized experience**.

---

# 2. DO NOT COPY THE OLD DESIGN

The existing website is only a reference for:

* Content
* Information architecture
* Business offerings
* Branding
* Existing functionality

Do **not** reproduce its old visual design.

We want to move away from:

* Generic WordPress layouts
* Excessive rectangular boxes
* Flat sections
* Basic image + text combinations
* Dated gradients
* Generic stock-template appearance
* Excessive borders
* Poor spacing
* Visually repetitive sections
* Large walls of text
* Old-fashioned navigation
* Unnecessary visual clutter

The new website should feel like it was designed from scratch by a professional modern product/design team.

---

# 3. DESIGN DIRECTION

The visual identity should be based around PrimeTrack's existing brand colors:

* Dark orange
* Light orange
* Black
* Red
* White

However, **do not use all of these colors aggressively at the same time.**

Use them intelligently.

The overall visual language should feel:

* Premium
* Modern
* Technical
* Trustworthy
* Professional
* Innovative
* Reliable
* Corporate
* Confident
* Clean

PrimeTrack operates in **GPS tracking, vehicle tracking, fleet management, telematics and related technology**, so the design should communicate technology and reliability without looking like a generic software startup.

Avoid making it look like a gaming website, crypto website, or overly futuristic AI landing page.

The design should communicate:

> "This is a serious company that I can trust with my vehicles, fleet, assets and business."

---

# 4. MAKE CLIENT CONFIDENCE A PRIMARY DESIGN OBJECTIVE

One of the most important objectives is to make visitors immediately feel that PrimeTrack is:

* Established
* Legitimate
* Technologically capable
* Reliable
* Professional
* Secure
* Experienced

The website should answer the subconscious question:

> "Why should I trust PrimeTrack with my vehicles and business?"

Use design, layout, typography, imagery, statistics, testimonials, trust signals, service explanations, technology explanations and strong calls-to-action to reinforce credibility.

Do not fabricate statistics, testimonials, certifications, clients or achievements.

Only use information that actually exists on the current website or information explicitly provided later.

---

# 5. MODERN WEBSITE EXPERIENCE

The website should feel significantly more modern than the existing WordPress version.

Use modern UI/UX principles such as:

* Strong visual hierarchy
* Generous whitespace
* Excellent typography
* Large but controlled hero sections
* Sophisticated cards
* Subtle shadows
* Layered sections
* Modern grids
* Visual storytelling
* Micro-interactions
* Smooth hover states
* Scroll-based animations where appropriate
* Subtle transitions
* Sticky navigation
* Strong CTA placement
* Responsive layouts
* Clear section separation

Animations should be **subtle and professional**.

Do not overload the website with animations.

Performance is more important than flashy effects.

---

# 6. NAVIGATION

The navigation should be completely redesigned.

Each major menu item should support a **hover dropdown / mega-menu experience** where appropriate.

For example:

**Products**

* Product/service categories
* Relevant subpages

**Solutions**

* Relevant solutions

**Industries**

* Relevant industries

etc.

However, determine the actual menu structure from the existing PrimeTrack website rather than inventing categories.

The navigation should:

* Be clean
* Be easy to understand
* Work beautifully on desktop
* Have appropriate mobile navigation
* Have clear hover states
* Have active-page states
* Use dropdown animations
* Avoid clutter
* Make important pages easy to access

For desktop:

**Hovering over a navigation item should open its dropdown.**

For mobile:

Use an appropriate expandable/collapsible menu instead of relying on hover.

The navigation should remain usable while scrolling, potentially through a sticky/fixed header.

---

# 7. HOMEPAGE

The homepage should be completely redesigned.

Do not simply recreate the existing homepage sections in the same order.

Instead, determine the best modern information hierarchy based on PrimeTrack's actual business.

The homepage should likely communicate, in a logical sequence:

1. What PrimeTrack does
2. The primary value proposition
3. Key products/services
4. Why customers should choose PrimeTrack
5. How the technology/solutions work
6. Industries/use cases
7. Trust/credibility
8. Supporting services/features
9. Strong call-to-action
10. Contact/conversion opportunity

But use your own UX judgment after auditing the existing website.

The homepage should immediately communicate the company's value within the first few seconds.

---

# 8. HERO SECTION

Create a high-quality modern hero section.

It should immediately communicate:

* What PrimeTrack does
* Who it serves
* Why it matters

Use a strong visual composition rather than simply:

> Heading

> Button

Consider more sophisticated layouts such as:

* Large typography

* Vehicle/fleet imagery
* GPS/map visualizations
* Layered UI elements

But keep it credible and business-focused.

Do not invent fake product interfaces or statistics merely for visual decoration.

* Interactive cards

# 13. IMAGES

Review the images currently used by the website.

Determine which images are still useful and which should be replaced.

Do not blindly reuse every existing image.

* Vehicles
* Fleet management
* GPS tracking
* Technology
* Security
* Logistics
* Businesses

Images should feel professional and consistent.

Avoid generic-looking stock photography whenever possible.

# 14. RESPONSIVENESS

The website must be fully responsive.

Design specifically for:

* Desktop
* Laptop
* Tablet
* Mobile

Do not build desktop first and simply "shrink" everything.

Mobile should have its own thoughtful layout decisions.

Pay particular attention to:

* Navigation
* Hero sections
* Typography
* Cards
* Images
* Buttons
* Forms
* Dropdowns
* Spacing
* Touch targets

---

Use:

* Modern CSS architecture
* Reusable components
* Clean component hierarchy
* Responsive design
* Semantic HTML
* Accessible UI
* Good performance practices

* Navbar

* Testimonial

---

# 16. CODE QUALITY

Write production-quality code.

Avoid:

* Massive components
* Duplicate code
* Hardcoded repeated markup
* Inline styling everywhere
* Unnecessary dependencies
* Poor naming
* Temporary hacks
* Unused files
* Dead code

Keep the codebase maintainable.

A future developer should be able to understand and modify the website easily.

---

# 17. SEO

The rebuilt website should preserve and improve the site's SEO potential.

Pay attention to:

* Semantic HTML
* Page titles
* Meta descriptions
* Heading hierarchy
* Internal linking
* Image alt text
* URL structure
* Structured content
* Performance
* Mobile usability

Do not unnecessarily change existing URLs if doing so could damage SEO.

If URL changes are necessary, identify them clearly and create an appropriate redirect strategy.

---

# 18. PERFORMANCE

The website should load quickly.

Avoid unnecessary:

* Huge images
* Heavy animation libraries
* Excessive JavaScript
* Unoptimized assets
* Unnecessary dependencies

Optimize images and assets appropriately.

The website should feel fast even on slower mobile connections.

---

# 22. DESIGN ORIGINALITY

Do not make the website look like a generic template.

Do not copy the visual style of random SaaS websites.

Do not create a clone of Stripe, Tesla, Apple, etc.

Use modern design principles, but develop a visual identity that feels uniquely **PrimeTrack**.

The orange/black/red/white brand palette should become part of that identity.

The final design should be recognizable as PrimeTrack even without seeing the logo.

---

# 23. WORKFLOW — FOLLOW THIS ORDER

Do NOT immediately start coding.

Follow this workflow:

### Phase 1 — Website Audit

First inspect the existing website thoroughly.

Create an internal understanding of:

* Pages
* Navigation
* Content
* Services
* Products
* Industries
* CTAs
* Images
* Forms
* Footer
* Important business information

### Phase 2 — Information Architecture

Determine the improved sitemap and navigation structure while preserving existing content.

### Phase 3 — Design System

Establish:

* Colors
* Typography
* Spacing
* Buttons
* Cards
* Borders
* Shadows
* Icons
* Animation principles
* Responsive breakpoints

### Phase 4 — UX Architecture

Determine the ideal structure for:

* Homepage
* Navigation
* Dropdowns
* Individual pages
* CTAs
* Forms
* Footer

### Phase 5 — Build

Then implement the website in React using reusable components.

### Phase 6 — Responsive Optimization

Test and refine desktop, tablet and mobile layouts.

### Phase 7 — Quality Review

Check:

* Broken links
* Missing content
* Navigation
* Dropdowns
* Responsiveness
* Accessibility
* SEO
* Performance
* Console errors
* Image loading
* Forms
* Buttons
* Animations

---

# 24. IMPORTANT CLAUDE CODE BEHAVIOR

Act as a combination of:

**Senior Frontend Engineer + Senior UI/UX Designer + Product Designer + Web Performance Engineer.**

Do not simply follow the existing website's design.

Think critically.

If the existing design is bad, improve it.

If a section can communicate the same information much better using another layout, redesign it.

If the navigation can be structured better, restructure it.

If content is repetitive, find a better presentation method without deleting the information.

Make design decisions based on the actual business and content you discover.

Do not ask me to make every tiny design decision.

Use professional judgment.

However, **do not make up factual business information.**

---

# 25. FINAL QUALITY BAR

When finished, the website should feel like a significant upgrade from the current WordPress website.

The reaction we want from a first-time visitor is:

> "This looks like a serious, modern technology company."

Not:

> "This looks like a redesigned WordPress template."

The final experience should feel:

**Modern + Premium + Trustworthy + Technical + Professional + Original + Fast.**

Before considering the project complete, compare the new implementation against the original website and verify that the important information and functionality have not been lost.

Build this as a **real production website**, not a visual mockup.
